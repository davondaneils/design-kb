# Brief: Forms and input

## Question it answers
How do we get accurate data from people with the least effort and the fewest errors?

## After reading, a designer can decide
- Which questions to ask at all (question protocol), and in what order.
- Layout: single column, label position, field width, grouping, one thing per page vs one long page.
- Validation timing, error message placement and wording, error summary behavior.
- Input types, autocomplete tokens, masks, date entry, passwords, one-time codes.
- Button states during submission; whether to disable submit.

## Must cover
- GOV.UK form structure and error summary patterns.
- Inline validation research (Etre via Wroblewski) and Baymard's three inline validation rules.
- Placeholder-as-label failures (NN/g, Baymard).
- Baymard checkout field counts and abandonment reasons.
- WCAG 2.2 3.3.7 redundant entry, 3.3.8 accessible authentication; never block paste.
- Adam Silver on disabled buttons.

## Test briefs it should pass
- "Sign-up form for a B2B SaaS trial."
- "Mobile checkout for a DTC brand."
